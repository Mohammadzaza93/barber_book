# BarberBook — تطبيق حجوزات صالونات الحلاقة

تطبيق Flutter لإدارة حجوزات صالونات الحلاقة، بواجهة عربية/إنجليزية (RTL) وقاعدة بيانات Firebase.
يشمل لوحة تحكم كاملة للموظفين: مواعيد، خدمات، حلاقون، خصومات، نفقات، تقييمات، تقارير، إعدادات،
بالإضافة إلى صفحة حجز إلكترونية عامة يستخدمها العملاء.

## المميزات

- تسجيل دخول وإنشاء صالون جديد (معالج إعداد من 5 خطوات)
- شاشة رئيسية بإحصائيات ورسم بياني شهري
- إدارة المواعيد: إنشاء/تعديل/إلغاء/تأكيد، حالات متعددة، حجوزات عامة قيد المراجعة
- إدارة الخدمات، الحلاقين وساعات عملهم الأسبوعية، أوقات عدم التوفر
- خصومات (نسبة أو مبلغ، كود قابل للاستخدام من صفحة الحجز)
- نفقات وتقارير شهرية (أرباح، رسوم الحلاقين، مصاريف، خدمات شائعة)
- تقييمات العملاء ومراجعتها
- صفحة حجز عامة: خدمات متعددة + اختيار حلاق + مواعيد متاحة + كود خصم + وديعة
- طلب موعد خارج ساعات العمل (يظهر للإدارة كطلب قيد المراجعة)
- تتبع الحجز برقم الهاتف مع إمكانية التقييم
- تذكيرات (WhatsApp/بريد إلكتروني) وإشعارات محلية عند الحجز
- تصدير موعد بصيغة ICS / فتحه في Google Calendar
- اللغتان العربية (افتراضية) والإنجليزية

## المتطلبات

- Flutter SDK (3.27 أو أحدث) مع Dart 3.x
- مشروع Firebase (خطة Blaze اختيارية للاستفادة من التحديثات في الوقت الحقيقي)
- `flutterfire_cli` (أحدث إصدار)

## خطوات التشغيل

```bash
# 1) تنفيذ داخل مجلد المشروع
flutter pub get

# 2) إنشاء مجلدات المنصات (مرة واحدة فقط إذا لم تكن موجودة)
flutter create . --platforms=android,ios --org com.yourorg

# 3) إنشاء lib/firebase_options.dart الفعلي
#    (يتطلب أن تكون مسجلاً في Google Cloud)
dart pub global activate flutterfire_cli
flutterfire configure

# 4) توليد ملفات الترجمة
flutter gen-l10n

# 5) التحليل والبناء
flutter analyze
flutter run
```

## نموذج بيانات Firestore

```
shops/{shopId}
├── ownerId, createdAt
├── ساعات العمل والإعدادات (BookingSettings)
├── services/   → وثيقة لكل خدمة
├── employees/  → وثيقة لكل حلاق (مع جدول ساعات أسبوعي)
├── appointments/ → وثيقة لكل موعد
├── discounts/  → أكواد الخصم
├── expenses/   → النفقات
├── feedback/   → تقييمات العملاء
└── requests/      → طلبات المواعيد خارج الأوقات (تُحوَّل إلى مواعيد عند الموافقة)
```

## ملاحظات

- صفحة الحجز العامة متاحة من زر التقويم في الشاشة الرئيسية ومن إعدادات صفحة الحجز (معاينة).
  لإتاحتها للعملاء خارج التطبيق، تحتاج ربطها برابط ويب (Firebase Hosting + Dynamic Links).
- الإشعارات المحلية والتذكيرات تعتمد على المنطقة الزمنية `Asia/Riyadh`.
- قبل أول تشغيل فعلي على جهاز، ثبّت Flutter ثم نفّذ خطوات "خطوات التشغيل" أعلاه — لا يزال
  `lib/firebase_options.dart` يحوي قيماً وهمية إلى أن تنفّذ `flutterfire configure`.


## الأمان قبل النشر

قواعد Firestore وStorage في هذا المستودع مقفلة افتراضيًا، وتسمح بإدارة بيانات المحل فقط للمستخدم المصادق عليه الذي يطابق `ownerId` في وثيقة `shops/{shopId}`. لا تعِد إلى استخدام `allow read, write: if true`.

قبل النشر، راجع القواعد باستخدام Firebase Emulator أو Firebase CLI، ثم انشرها من حساب المشروع الصحيح فقط:

```bash
firebase use <your-firebase-project-id>
firebase deploy --only firestore:rules,storage
```

مسار الشعار المسموح به هو `shops/{shopId}/logo`، وتُقبل ملفات الصور فقط بحجم أقل من 5MB. إذا أُضيفت صفحة حجز عامة لاحقًا، فيجب تصميم صلاحيات عميل منفصلة أو استخدام Cloud Functions؛ لا تفتح مجموعات المواعيد كاملة للزوار.

## إعداد Firebase الفعلي

لا تستخدم القيم الوهمية في `lib/firebase_options.dart` في بيئة الإنتاج. نفّذ `flutterfire configure` بعد تسجيل الدخول إلى مشروع Firebase الصحيح، ثم تحقق من تفعيل Email/Password Authentication وFirestore وStorage وCloud Messaging حسب المنصة المستهدفة. لا تُرسل ملفات إعداد الإنتاج إلى مستودع عام إذا كانت سياسة المشروع تمنع ذلك؛ مفاتيح Firebase العامة ليست بديلًا عن قواعد الأمان.


## الميزات الجديدة

### الإشعارات والتذكيرات

يطلب التطبيق صلاحية الإشعارات عند التشغيل، ويستخدم الإشعارات المحلية لتذكير العميل قبل الموعد وفق التوقيتات الموجودة في إعدادات الصالون. تتم جدولة التذكيرات لكل موعد، بما في ذلك المواعيد الأسبوعية المتكررة، ويُلغى التوقيت السابق قبل إعادة الجدولة. أضيفت صلاحيات Android للإشعارات واستعادة الجدولة بعد إعادة تشغيل الجهاز. ويظل Firebase Cloud Messaging متاحًا للإشعارات القادمة من الخادم.

### لوحة التحكم المتقدمة

تعرض لوحة التحكم الإيرادات الشهرية، صافي الربح بعد خصم المصروفات، عدد العملاء، متوسط قيمة الفاتورة، نسبة عدم الحضور، ونسبة إكمال المواعيد. كما تعرض رسمين بيانيين لآخر سبعة أيام: رسم الإيرادات ورسم عدد الحجوزات، إضافة إلى الخدمات الأكثر طلبًا وأداء الموظفين.

### الحلاق المفضل والخدمات الإضافية

يمكن للعميل اختيار خدمة أساسية ثم إضافة خدمات إضافية إلى الموعد نفسه. تُحفظ كل المعرفات داخل `serviceIds` ويُعاد حساب إجمالي السعر والمدة والعربون بناءً على القائمة الكاملة. كما يستطيع العميل حفظ الحلاق الحالي كمفضل، ويُختار تلقائيًا في الحجز التالي على الجهاز نفسه وللمحل نفسه.

### اختبارات الميزات

أضيفت اختبارات لـ `AnalyticsService` تغطي الحجوزات اليومية، نسبة الإكمال، وصافي الربح، بالإضافة إلى اختبارات حساب الخصومات والعربون الموجودة سابقًا. بعد تثبيت Flutter، شغّل:

```bash
flutter pub get
flutter analyze
flutter test
```


## ميزات إدارة الأعمال الجديدة

أضيفت شاشة **أدوات الأعمال** إلى لوحة الإدارة، وتضم خمس وحدات مترابطة:

- **استعراض الأعمال:** إضافة صور الأعمال السابقة عبر روابط صور، وتصنيفها ووصفها، ثم عرضها في معرض يمكن فتحه من صفحة الحجز.
- **برنامج الولاء:** إنشاء حسابات للعملاء، حفظ النقاط، ورفع النقاط عند الزيارات المتكررة مع مستويات Bronze وSilver وGold وPlatinum.
- **تنظيم الموظفين والكراسي:** تعريف الكراسي وربط الموعد بالحلاق والكرسي المختار، مما يسهّل منع التداخل في الجدول التشغيلي.
- **الطابور:** تسجيل العملاء في طابور الانتظار، توزيعهم على الحلاقين، ونقل الحالة من انتظار إلى قيد الخدمة ثم مكتمل.
- **المدفوعات والترويج:** تسجيل المدفوعات حسب الطريقة، عرض إجمالي المدفوعات، والانتقال مباشرة إلى إدارة الخصومات والعروض الترويجية.

تُحفظ البيانات الجديدة في المجموعات الفرعية التالية تحت المحل:

```text
shops/{shopId}/portfolio
shops/{shopId}/loyalty
shops/{shopId}/chairs
shops/{shopId}/queue
shops/{shopId}/payments
```

وتخضع جميعها لقواعد Firebase الحالية التي تقصر الوصول على مالك المحل المصادق عليه.


## إدارة العملاء والولاء والكراسي

تضم أدوات الأعمال الآن سجلًا مستقلًا للعملاء يُبنى تلقائيًا من المواعيد المكتملة، ويعرض حالة العميل (أول زيارة، متكرر، دائم)، عدد الزيارات، إجمالي الإنفاق، تاريخ آخر زيارة، متوسط الفاصل بين الزيارات، الوقت والخدمات والحلاق المفضلين، ومؤشرًا للعملاء الذين تجاوزوا مدة الغياب المحددة في قاعدة الولاء. يمكن تعديل الملف يدويًا وإضافة الملاحظات وتفعيل أو إيقاف رسائل العروض.

يمكن للمالك إنشاء عدة قواعد لكسب النقاط، مثل النقاط لكل زيارة أو لكل وحدة نقدية أو المكافأة الإضافية والحد الأدنى للفاتورة ومدة الغياب. كما يمكن إنشاء هدايا بنقاط تكلفة ومستوى أدنى ومخزون، ثم استبدالها من حساب العميل عبر عملية ذرية تمنع خصم النقاط دون تحديث المخزون.

أضيفت إدارة متكاملة للكراسي تشمل رقم الكرسي واسمه والحلاق المسؤول وحالة التشغيل، مع تسجيل مستلزمات كل كرسي وكمياتها وتكلفة الوحدة وحد إعادة الطلب. وتعرض شاشة ربحية الكراسي الإيرادات والزيارات المكتملة ومدة العمل والإشغال التقريبي وتكلفة المواد. يستطيع المالك إدخال الربح الأسبوعي المعتمد يدويًا؛ وعند تركه فارغًا يحسب التطبيق الربح تلقائيًا من الإيراد مطروحًا منه تكلفة المواد.

تُحفظ الوحدات الجديدة تحت `shops/{shopId}` في مجموعات `customers` و`loyaltyRules` و`loyaltyGifts` و`chairSupplies` و`chairWeeklyProfits`. كما أصبحت المدفوعات مرتبطة اختياريًا بالكرسي والحلاق وتكلفة المواد، وأصبحت المواعيد الإدارية والعامة تحفظ `customerId` و`chairId` عند توفرهما.
